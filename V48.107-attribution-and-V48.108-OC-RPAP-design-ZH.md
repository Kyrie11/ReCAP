# V48.107 归因与 V48.108 OC-RPAP 设计

## 结论摘要

V48.107 工程与科学门控通过。正式状态是 `FIRST_BLOCK_NOMINAL_INVARIANT_ACTION_ORIENTATION_STOP`：State GO，Support STOP，Reserve STOP，因此不是 Partial GO。

V48.107 的重要之处不是“训练失败”。两套 variant 的 train/dev ordinal objective 都稳定下降到 epoch 59，并且 nominal State 与 V48.103 完全一致。第一 Stage-I block 确实可以重排 candidate response；但是这种重排没有形成跨 balanced/precision、dev/certificate 的统一 signed coordinate。最典型的是 Support：balanced certificate-Near 明显变强，而 precision certificate-Near 反向退化；precision certificate-Contact 较强，但 precision dev-Contact 反向退化。Reserve 的 certificate-Near/Contact 则有一致正信号，说明 debt/recovery 轴比 Support 更接近可迁移。

因此 V48.107 新增的核心论据是：

`within-group ordinal surrogate improvement != population-invariant signed recovery orientation`。

这与前几轮共同形成：

`static sufficiency != control sufficiency`
`+ parameter factorization != representation factorization`
`+ response-loss reduction != cross-distribution control sufficiency`
`+ action association != signed action equivariance`
`+ ordinal training improvement != invariant orientation`。

## 为什么不继续训练第一 block

V48.107 已经验证单一 `first block + exact nominal anchoring + equal-weight sign-only ordinal loss` family。继续扫 epoch/LR/head/width 会把“优化能力”和“信息/路径缺陷”重新纠缠，而且违反预注册分支。Pairwise ranking surrogate 本身也没有理由保证 OOD population ranking 一致，因此 train/dev loss 继续下降不是继续加 epoch 的授权依据。

## Near / Contact

Near 的 static state 已不再是主要缺陷。当前问题是 Support 与 Reserve 的 action evidence 能否在 balanced/precision 与 dev/certificate 中保持同一 signed orientation。V48.107 没有让这一问题单调收敛，Support 仍有跨 variant 摆动；Reserve 在 certificate population 上明显变好。

Contact 的 certificate debt separation 是本轮最明确的正信号之一，但 dev/certificate 尚未同时闭合。真正问题仍是统一的 `candidate - nominal` signed recovery response，而不是 Contact-specific router。

## V48.108: Raw-to-Projected Action Pathway Audit

V48.108 不训练模型。它只回答 V48.107 已预注册的上游问题：missing Support orientation 是在 raw candidate-prefix/control 变量中已经存在、后来被组织坏了，还是在 projection 之前就没有形成？

候选路径完全由历史 `StructuredTokenEncoder` 固定：

- ego (9)
- prefix_param (5)
- macro + scalar (22)
- prefix_state (80)
- control (40)

共 156 维。投影后对应任何 Transformer 之前的五个固定 semantic token，共 960 维。

对每个投影 `y = Wx+b`，candidate-minus-nominal 后有 `Delta y = W Delta x`。V48.108 检查 `W` 是否满列秩、奇异值/条件数，并用 pseudoinverse 在真实 candidate delta 上重建 raw delta。如果满列秩且重建误差很小，则线性 projection 在信息论/线性代数意义上没有把 raw action delta 删除；之后的失败必须归到 interaction/organization/relational sufficiency，而不是“投影容量太小”。

同时分别在 raw 156-D 与 projected 960-D pathway 上复用 V48.102 的同一 target-specific probe：Support 用 delta，Reserve 用 state-conditioned delta，仍用相同 within-group shuffle null 与相同 held-out population。

### 预注册分支

- Raw Support + Reserve 都 GO：不再训练 Transformer；进入一次 direct nominal-invariant projected-path response carrier。
- Raw Support GO / Reserve STOP：只审计 raw candidate-to-scene reserve/debt interaction。
- Raw Reserve GO / Support STOP：只审计 raw candidate-to-scene support-establishment interaction。
- 两轴都 STOP：raw candidate pathway 单独不足，下一步只做固定 raw candidate-to-scene relational interaction audit。
- Projection 非 injective：只允许最小 projection-preservation repair，不允许 source/broad encoder。

V48.108 的目的不是增加一个新模型组件，而是决定后续训练到底应该发生在 projection、candidate-to-scene interaction，还是更下游的 transport，从而继续维持可因果归因的迭代链。
