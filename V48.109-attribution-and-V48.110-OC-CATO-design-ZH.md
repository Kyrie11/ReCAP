# V48.109 归因与 V48.110 OC-CATO 预注册设计

## 1. V48.109 双门控

V48.109 的工程与科学门控通过：runtime / balanced / precision / comparison / pipeline 与 audit archive 自洽；runtime SHA 与上传 drop-in 一致；PT 只保存闭式 probe 的 scaler / coefficient / metadata。Stage-I、root decoder、source、planner 均未训练。所有 registered fit 都是 float64 sample-dual class-balanced ridge，`lambda=1/N`，严格凸、唯一全局解，最大 normal-equation residual 约 `4.3e-10`。

存在一个非阻断 lineage 注记：V48.109 记录的 V48.108.1 pipeline byte SHA 与上一轮上传副本不同，但 authoritative V48.108.1 comparison SHA 完全一致，pipeline version/status/branch 一致，且 V48.108 只用于授权分支，不把其数值输入 V48.109。从 V48.110 起冻结 authoritative prerequisite **comparison SHA** 作为 branch owner。

## 2. 正式判决

V48.109 = **Formal Full STOP**：

- convex base Support STOP；
- convex base Reserve STOP；
- relational Support STOP；
- relational Reserve STOP；
- status = `RAW_SCENE_RELATIONAL_STOP`。

因此关闭 `u^T(w+Wc)` 的 candidate-invariant pooled-scene bilinear orientation family。

## 3. V48.109 最关键的正向信号

### Support

Convex base 仍保留强 dev-Near action signal：`AUC≈0.758`、shuffle margin≈`+0.305`、top-1 lift `+0.6`；dev-Contact `AUC≈0.636`，也有正 shuffle/top-1 margin。因此不是 generic action blindness。

Relational context 对 certificate-Near Support 产生巨大增益：`0.109 -> 0.818`，但同时把 dev-Near `0.758 -> 0.453`。这说明 context 有真实信息，但 pooled bilinear field 没有形成跨 population 共用的 orientation。

### Reserve/debt

Convex base dev-Near Reserve 从 V48.108 registered raw probe 的 `AUC=0` 变成 `AUC=1.0`，说明 finite-probe optimization/conditioning 可以极大改变可读性，进一步证明：`probe STOP != information-theoretic absence`。

Relational Reserve 对 certificate-Contact `0.486 -> 0.681`，却把 dev-Contact `0.510 -> 0.354`，并出现 negative shuffle/top-1 transfer。仍然是 context-dependent but non-invariant 的模式。


新增关键理论链：

```text
unique convex optimum != correct invariant function class
```

因此“继续增加 epoch / LR / Transformer depth / pooled context MLP”没有理论依据。

## 5. 对 invariant object 的修正

V48.109 不否定 “same function across populations”。它否定的是更窄的：

```text
omega(c) = one candidate-invariant covector for one scene
score(u,c) = u^T omega(c)
```

原因是 candidate prefix 本身会改变 active agent / active constraint。一个 scene 内不同 action 可能由不同 agent 成为 limiting constraint，因此 orientation 应允许 candidate-conditioned active-set switching。

更强 constructive hypothesis：

```text
score(u,A) = F(u,{a_i})
```

其中 `F` 包含：

1. candidate-conditioned active-constraint selection；
2. 对选中 active constraint 的 signed recovery orientation；
3. 同一个 `F` 必须跨 Near/Contact、dev/certificate population 共用。

Invariant 属于 **selection-and-orientation rule**，不是固定 latent axis，也不只是 candidate-invariant scene-conditioned axis。

## 6. Near / Contact 统一解释

Near：Support local ordering 已经强，但 certificate transfer 会翻转；Reserve 在不同 probe/solver 中可读性强烈变化。真正问题是“哪个 interaction constraint 对当前 candidate 是 active，以及沿哪个方向建立 positive reserve”。

Contact：certificate debt signal 能被某些 relation/interaction family 暴露，但 dev/certificate 或 shuffle null 不稳定。真正问题是“当前 candidate 是否在偿还 controlling active constraint 的 negative debt”。

二者统一为：

```text
good candidate -> improves the same signed recovery semantics
```

只是 Near 位于正 reserve 建立侧，Contact 位于负 debt 偿还侧。不引入 runtime regime router。

## 7. V48.110 OC-CATO

全称：**Observation-Consistent Candidate-to-Agent Active-Constraint Topology Orientation Audit**。

### 7.1 唯一实验变量

保持 V48.109 完全相同的闭式严格凸 ridge solver，只改变 fixed feature map。

### 7.2 Candidate-specific active constraint

从历史 80-D prefix-state block 只使用前 8 个完整 9-D prefix states。对每个当前 observed agent：

- raw token 解码当前相对位置、速度、length/width；
- 使用 observation-only constant-velocity continuation；
- 使用历史 recovery-witness 已采用的 circle support approximation；
- 计算 candidate prefix 与 agent 的最小 signed clearance。

选取：

```text
active1 = minimum-clearance agent
active2 = second minimum-clearance agent
nearest = current nearest agent
```

`active1/2` 随 candidate 改变，因此可以表达 within-scene constraint switch。selector 不读取 teacher future、不用 Near/Contact ID、不学习参数、不做 threshold sweep。

### 7.3 三个同 solver family

- `base`: `u`，必须重现 V48.109 convex-base AUC；
- `nearest`: `[u, u⊗a_nearest]`，candidate-invariant local-agent control；
- `topology`: `[u, u⊗a_active1, u⊗a_active2, u*c1, u*(c2-c1)]`，固定 3,588-D。

Support：`u = candidate - nominal raw delta`。

Reserve/debt：`u = delta * (1+tanh(nominal raw state))`。

所有 relation term 均乘 `u`，因此 nominal `u=0` exact zero。

### 7.4 Null

Within-group shuffle 必须把整个 candidate identity 一起 roll：

```text
u + active1 + active2 + clearance topology
```

agent set 保持 scene 固定。这样 shuffle 不会偷带原 candidate 的 active topology。

### 7.5 Gate

沿用 unchanged action gate：

```text
AUC >= .65 and AUC_true - AUC_shuffle >= .05 in >=6/8 cells
>=3/4 roles with Near + Contact
top1 lift >= .10 in >=4/8 cells with Near + Contact
```

Topology family 是正式 branch owner；nearest 只做 causal control。

### 7.6 预注册分支

- Support + Reserve GO：promotion `candidate-conditioned active-constraint recovery orientation`，下一步只做一次 nominal-invariant topology response-carrier integration。
- Support GO / Reserve STOP：只审计 signed debt active-constraint flow。
- Reserve GO / Support STOP：只审计 Support-establishment active-constraint switch。
- 两轴 formal STOP，但两轴 top-1 local-order gate 都成立：保持 feature 不变，只做一次 **convex pairwise ranking audit**，隔离 pointwise calibration vs within-group ordering。
- 其他 STOP：关闭固定 CV active-set topology family，进入 constraint-native candidate-agent geometry audit；不增加 generic encoder/source capacity。

## 8. Main Stack

V48.109/110 都是 audit，不修改 Main Stack。继续保留：

`OC-MERO + actuator-realizable executable recovery + counterfactual equivalence-partition transport + identifiability before capacity + support-establishment/signed reserve-debt + recovery base-state chart + RIFA`。

只有 active-topology/full control-sufficient mechanism Full GO 后，才考虑替换 recovery base-state chart。
